# Mobile Agent Protocol V0.1

Status: HMR-106 protocol patch 0.1.1, 2026-09-02.

The normative contract is the checked-in Draft 2020-12 schema bundle at
`hermes_mobile/protocol/schemas/v0.1/`. This document explains how to use it;
it does not replace the schemas or ADR-0002.

## Messages

| `message_type` | Direction | Purpose |
|---|---|---|
| `compatibility.offer` | both | Advertise patch range, bundle/Tool digests and features |
| `compatibility.selection` | negotiator → peer | Bind the selected patch and accepted features |
| `tool.execution_request` | Hermes adapter → Runtime | Request policy evaluation; never direct Android authority |
| `action.authorized` | protected broker → Android PEP | Carry short-lived, exact-action authorization |
| `tool.execution_result` | execution plane → Runtime | Report execution, state refs, error and verification separately |
| `mobile.event` | Android/Runtime → Hermes | Normalize an event without inheriting execution authority |

All V0.1 messages and Tool parameter objects are closed. Optional future data
must use a negotiated namespaced `extensions` entry; an unknown top-level key
is a protocol error.

## Compatibility

1. Decode both offers using strict JSON and the offer schema.
2. Require each range to stay within one major/minor line.
3. Intersect the ranges with the local minimum accepted version.
4. Require identical bundle and all 13 Tool schema digests.
5. Require each peer to support the other peer's required features.
6. Select the highest common patch and sorted feature intersection.

Failure at any step returns `PROTOCOL_INCOMPATIBLE` and prevents dispatch.
Negotiation does not grant policy permission or device authority.

## Wire limits

| Limit | V0.1 value |
|---|---:|
| Encoding | strict UTF-8 JSON |
| Document size | 1,048,576 bytes |
| Nesting | 64 levels |
| Items per object/array | 4,096 |
| Integer range | ±9,007,199,254,740,991 |
| Duplicate object keys | rejected |
| NaN / Infinity | rejected |
| Authorization lifetime | at most 30 seconds |

## Schema release process

After an intentional schema edit, run:

```bash
python3 scripts/mobile/generate_protocol_manifest.py
scripts/run_tests.sh tests/mobile/contract
```

Review the changed schema, its per-file digest, bundle digest and affected
fixtures together. A digest change is a protocol change, even when the JSON
shape appears backward compatible. Do not hand-edit `manifest.json`.

## Canonical digests

Authorization-relevant V0.1 objects use an integer-only canonical JSON domain:
object keys use UTF-16 code-unit order, strings use JSON escaping, arrays keep
order and integers use their shortest decimal representation. Floating-point
values and unpaired Unicode surrogates are rejected. SHA-256 digests are
serialized as `sha256:` followed by 64 lowercase hexadecimal characters.

The exact V0.1 logical action digest object contains `protocol_line`
(`major.minor`), `request_id`, `task_id`, `device_id`, `tool`, `parameters`,
`state_precondition`, `verification`, `idempotency_key`, `deadline`,
`effective_target` and `effective_risk`. Attempt, expiry, nonce, session and
signature metadata are excluded so authorization may be renewed only for the
same approved logical action. The signed authorization still binds those
excluded transport/replay fields separately.

## Ownership boundary

The Python codec validates planner/Runtime messages. The Kotlin codec validates
the device-side envelope and Tool parameters. Neither codec dispatches a Tool.
HMR-104 owns the sole Capability Registry and Tool Router; HMR-105 owns the
first real `phone.current_app` implementation. HMR-106/ADR-0004 define its
coherent PhoneState generation and protected artifact boundary.

## PhoneStateRef 0.1.1

Every non-null state reference explicitly carries its predecessor,
foreground package/activity claim, capture status/errors, transition and a
basis-tagged screen fingerprint. The current implementation supports only
`WINDOW_IDENTITY`, which hashes the already disclosed package/activity fields.
It does not claim pixel, dialog, text or UI-tree equivalence. UI and screenshot
content remain separately protected artifacts.
